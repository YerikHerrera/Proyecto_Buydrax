2. REQUISITOS PREVIOS
--------------------------------------------------------------------------------

Para ejecutar el proyecto desde cero se necesita:

- Git
- PostgreSQL 14 o superior
- Python 3.10 o superior
- Node.js 18 o superior
- npm
- DBeaver, pgAdmin o psql para ejecutar los scripts SQL

Versiones utilizadas durante el desarrollo/reconstrucción actual:

- Python 3.14.3
- Node.js 24.x
- npm 11.x
- PostgreSQL 18.x

Las versiones pueden variar entre equipos. Las dependencias exactas del backend
se encuentran en:

    backend/requirements.txt

y las dependencias del frontend se encuentran en:

    frontend/package.json

--------------------------------------------------------------------------------
3. OBTENER EL PROYECTO
--------------------------------------------------------------------------------

Si el proyecto todavía no está en el equipo:

    git clone https://github.com/YerikHerrera/Proyecto_Buydrax.git
    cd Proyecto_Buydrax

La rama principal actual es:

    master

La rama main se conserva como parte del historial anterior del proyecto.

--------------------------------------------------------------------------------
4. PASO A PASO - BASE DE DATOS
--------------------------------------------------------------------------------

IMPORTANTE:

El archivo:

    BASE_DE_DATOS_BUYDRAX_CORREGIDA.sql

NO contiene instrucciones CREATE DATABASE ni cambia de conexión
automáticamente.

Por eso, se debe disponer primero de una base PostgreSQL sobre la cual ejecutar
los scripts.

El entorno utilizado actualmente trabaja con:

    Motor:      PostgreSQL
    Host:       localhost
    Puerto:     5432
    Usuario:    postgres
    Base:       postgres

También puedes utilizar otra base de datos. Si lo haces, deberás colocar ese
nombre en DATABASE_URL dentro de backend/.env.

------------------------------------------------
4.1 Verificar PostgreSQL
------------------------------------------------

Asegúrate de que PostgreSQL esté instalado y ejecutándose.

En Windows puede comprobarse desde:

    Servicios de Windows

buscando el servicio correspondiente a PostgreSQL.

También se puede comprobar mediante DBeaver, pgAdmin o psql.

------------------------------------------------
4.2 Ejecutar los scripts SQL
------------------------------------------------

Los scripts deben ejecutarse EN ESTE ORDEN:

    1. BASE_DE_DATOS_BUYDRAX_CORREGIDA.sql
    2. SQL_RESET_PASSWORD_Admin123.sql

El primer script crea la estructura y carga los datos correspondientes al
proyecto.

El segundo script establece la contraseña de prueba:

    Admin123!

para los usuarios existentes.

------------------------------------------------
4.3 Desde DBeaver
------------------------------------------------

1. Abrir DBeaver.
2. Conectarse al PostgreSQL local.
3. Seleccionar la base de datos que se utilizará para Buydrax.
4. Abrir:

       BASE_DE_DATOS_BUYDRAX_CORREGIDA.sql

5. Ejecutar el script completo.
6. Abrir:

       SQL_RESET_PASSWORD_Admin123.sql

7. Ejecutar el segundo script completo.

------------------------------------------------
4.4 Desde psql
------------------------------------------------

Si se utiliza la base de datos postgres:

    psql -U postgres -d postgres -f BASE_DE_DATOS_BUYDRAX_CORREGIDA.sql
    psql -U postgres -d postgres -f SQL_RESET_PASSWORD_Admin123.sql

Si se utiliza otra base de datos, reemplazar "postgres" por el nombre
correspondiente.

------------------------------------------------
4.5 Verificar usuarios
------------------------------------------------

Opcionalmente:

    SELECT id_usuario, correo, id_perfil, estado
    FROM usuarios
    ORDER BY id_usuario
    LIMIT 15;

Los perfiles principales son:

--------------------------------------------------------------------------------
5. PASO A PASO - BACKEND FASTAPI
--------------------------------------------------------------------------------

Abrir una terminal y entrar en:

    cd Proyecto_Buydrax\backend

En Linux/macOS:

    cd Proyecto_Buydrax/backend

------------------------------------------------
5.1 Crear entorno virtual
------------------------------------------------

Windows PowerShell:

    python -m venv .venv
    .\.venv\Scripts\Activate.ps1

Windows CMD:

    python -m venv .venv
    .venv\Scripts\activate

Linux/macOS:

    python3 -m venv .venv
    source .venv/bin/activate

------------------------------------------------
5.2 Instalar dependencias
------------------------------------------------

Con el entorno virtual activado:

    python -m pip install --upgrade pip
    pip install -r requirements.txt

------------------------------------------------
5.3 Crear el archivo .env
------------------------------------------------

El repositorio contiene:

    backend/.env.example

pero NO contiene un .env real.

Cada equipo debe crear su propio .env.

Windows PowerShell:

    Copy-Item .env.example .env

Linux/macOS:

    cp .env.example .env

Después editar:

    backend/.env

Ejemplo para el entorno actual:

    DATABASE_URL=postgresql+psycopg2://postgres:TU_PASSWORD@localhost:5432/postgres
    SECRET_KEY=GENERA_UNA_CLAVE_SECRETA_LARGA_Y_ALEATORIA
    ALGORITHM=HS256
    ACCESS_TOKEN_EXPIRE_MINUTES=480

    APP_NAME=Buydrax API
    APP_ENV=development
    DEBUG=True
    API_PREFIX=/api

IMPORTANTE:

- Reemplazar TU_PASSWORD por la contraseña local de PostgreSQL.
- Generar una SECRET_KEY propia para cada entorno.
- No copiar una SECRET_KEY real desde otro equipo.
- No subir backend/.env a GitHub.
- El archivo .env está excluido mediante .gitignore.

Si se necesita generar una SECRET_KEY con Python:

    python -c "import secrets; print(secrets.token_urlsafe(32))"

Copiar el resultado en:

    SECRET_KEY=...

------------------------------------------------
5.4 Ejecutar el backend
------------------------------------------------

Desde:

    Proyecto_Buydrax/backend

con el entorno virtual activado:

    uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

La API queda disponible en:

    http://127.0.0.1:8000

Documentación Swagger:

    http://127.0.0.1:8000/docs

Health check:

    http://127.0.0.1:8000/health

OpenAPI:

    http://127.0.0.1:8000/openapi.json

Dejar esta terminal abierta mientras se utiliza el sistema.

--------------------------------------------------------------------------------
6. PASO A PASO - FRONTEND REACT + VITE
--------------------------------------------------------------------------------

Abrir OTRA terminal.

Entrar en:

    cd Proyecto_Buydrax\frontend

En Linux/macOS:

    cd Proyecto_Buydrax/frontend

------------------------------------------------
6.1 Instalar dependencias
------------------------------------------------

Ejecutar:

    npm install

No es necesario subir node_modules al repositorio.

------------------------------------------------
6.2 Configuración de conexión al backend
------------------------------------------------

El frontend contiene:

    frontend/.env.example

con:

    VITE_API_BASE_URL=http://127.0.0.1:8000/api

El prefijo actual del backend es:

    /api

NO utilizar:

    /api/v1

si se está trabajando con la configuración actual del proyecto.

Si se desea crear un .env local:

Windows PowerShell:

    Copy-Item .env.example .env

Linux/macOS:

    cp .env.example .env

El archivo frontend/.env también es local y no debe subirse a Git.

------------------------------------------------
6.3 Ejecutar el frontend
------------------------------------------------

Ejecutar:

    npm run dev

Vite mostrará la dirección local en la terminal.

Normalmente:

    http://localhost:5173

Abrir esa dirección en el navegador.

11. PROBLEMAS FRECUENTES
--------------------------------------------------------------------------------

------------------------------------------------
11.1 Error de conexión a PostgreSQL
------------------------------------------------

Verificar:

    - PostgreSQL está ejecutándose.
    - El usuario es correcto.
    - La contraseña de PostgreSQL es correcta.
    - El puerto es correcto.
    - DATABASE_URL apunta a la base correcta.
    - Los scripts SQL fueron ejecutados.
    - Las tablas existen en la base seleccionada.

La configuración de conexión se encuentra en:

    backend/.env

------------------------------------------------
11.2 Login con credenciales incorrectas
------------------------------------------------

Verificar que:

    SQL_RESET_PASSWORD_Admin123.sql

se haya ejecutado DESPUÉS de:

    BASE_DE_DATOS_BUYDRAX_CORREGIDA.sql

Contraseña de prueba:

    Admin123!

------------------------------------------------
11.3 Frontend no conecta con backend
------------------------------------------------

Primero comprobar:

    http://127.0.0.1:8000/docs

Si Swagger no abre, el backend no está ejecutándose correctamente.

Después revisar:

    frontend/.env

Debe utilizar:

    VITE_API_BASE_URL=http://127.0.0.1:8000/api

El prefijo actual es:

    /api

no:

    /api/v1

------------------------------------------------
11.4 Puerto 8000 ocupado
------------------------------------------------

Se puede utilizar otro puerto:

    uvicorn app.main:app --reload --host 127.0.0.1 --port 8001

Después cambiar:

    VITE_API_BASE_URL=http://127.0.0.1:8001/api

en la configuración del frontend.

------------------------------------------------
11.5 Puerto 5173 ocupado
------------------------------------------------

Ejecutar Vite en otro puerto:

    npm run dev -- --port 5174

------------------------------------------------
11.6 Problemas con bcrypt / passlib
------------------------------------------------

Las versiones utilizadas por el proyecto están definidas en:

    backend/requirements.txt

Instalar las dependencias mediante:

    pip install -r requirements.txt

Si es necesario:

    python -m pip install --upgrade pip

--------------------------------------------------------------------------------
12. VARIABLES DE ENTORNO Y SEGURIDAD
--------------------------------------------------------------------------------

El repositorio contiene archivos de ejemplo:

    backend/.env.example
    frontend/.env.example

Los archivos reales:

    backend/.env
    frontend/.env

son locales.

NO deben subirse al repositorio.

Nunca colocar en README, documentación o Git:

    - Contraseñas reales de PostgreSQL
    - SECRET_KEY real
    - Tokens JWT
    - Credenciales privadas
    - Otros secretos del entorno

Cada equipo debe configurar sus propias variables de entorno.
